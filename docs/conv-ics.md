# conv-ics.py

iCalendar (.ics) parser and builder.

A pure-Python port of [loteoo/icsp](https://github.com/loteoo/icsp) (originally a bash + awk + sed + tr pipeline) following the TangoMan Heel microframework conventions.

## Overview

`conv-ics` converts iCalendar exports into CSV/TSV (and back) so the data can be piped through `grep`, `sort`, `column`, `xsv`, `q`, `csvkit` or `visidata`.

**The input format is auto-detected from the file extension:**

| Input extension | Direction           | Field delimiter                                |
|-----------------|---------------------|------------------------------------------------|
| `.ics`          | iCalendar → TSV/CSV | (output delimiter from `--delimiter`, CSV by default)   |
| `.csv`          | CSV → iCalendar     | `,`                                            |
| `.tsv`          | TSV → iCalendar     | TAB                                            |

**The default forward output layout is Google Calendar-compatible.** Use `--full` to opt back into the old "every field found in the file" dump.

The Python port preserves the original feature set while removing the shell dependencies: no `awk`, `sed`, `tr` or external `date` invocations are required at runtime.

## Requirements

- Python 3.10+
- Standard library only (no third-party dependencies)

## Usage

```bash
python3 conv-ics.py <input> [options]
```

If `--output` is omitted, the file is written to the current working directory with the same basename as the input and a new extension (`.csv`/`.tsv`/`.txt` for forward, `.ics` for reverse). Pass `--output -` to stream to stdout. When the input is a directory and `--recursive` is used, `--output` is **required** and must point to a directory.

## Options

| Flag                 | Description                                                                              |
|----------------------|------------------------------------------------------------------------------------------|
| `input`              | Path to an iCalendar, CSV or TSV file (positional, required) — direction is auto-detected |
| `--output`           | Output file or directory. Default: write a file next to the input with a new extension. Use `-` for stdout. Required when `--recursive` is used. |
| `--recursive`        | Process directories recursively; preserve directory structure when writing to a dir. Requires `--output <dir>`. |
| `--include`          | Include filter (glob pattern)                                                            |
| `--exclude`          | Exclude filter (glob pattern)                                                            |
| `--dry-run`          | Simulate actions without writing                                                        |
| `-v`, `--verbose`    | Increase verbosity (stackable: `-v`, `-vv`, `-vvv`)                                      |
| `--columns`          | Comma-separated list of fields (preserved order, case-insensitive) — only with `--full`  |
| `--delimiter`        | Field delimiter for the tabular output (default: `,` / CSV). Also sets the input delimiter if specified. |
| `--full`             | Output the full iCalendar dump (every field found in the file, in iCalendar/ISO form). The default is the Google Calendar-compatible CSV layout. |

### About `--delimiter`

- **`--delimiter`** sets both the **output** delimiter and the **input** delimiter, effectively overriding the extension-based auto-detection.
- For TSV output from a `.ics` file, use `--delimiter $'\t'`.

## Examples

### Forward conversion (ICS → CSV / TSV)

The default output is the Google Calendar-compatible CSV layout. Pass `--full` to get the raw iCalendar dump (every field found in the file, ISO-converted dates, etc.).

```bash
# Default: Google Calendar CSV (Calendar,Subject,Start Date,Start Time,End Time,Description,Attendee,Location)
python3 conv-ics.py calendar.ics

# Same, with TAB as the delimiter
python3 conv-ics.py --delimiter $'\t' calendar.ics

# Full iCalendar dump (old default): every column, ISO dates, DURATION, ...
python3 conv-ics.py --full calendar.ics

# Specific columns in a chosen order (only with --full)
python3 conv-ics.py --full --columns 'dtstart,summary,duration' calendar.ics

# Custom delimiter with --full
python3 conv-ics.py --full --delimiter ';' --columns 'uid,summary,dtstart' calendar.ics
```

### Reverse conversion (CSV / TSV → ICS)

The direction is auto-detected from the file extension — no flag required:

```bash
# CSV input
python3 conv-ics.py events.csv > events.ics

# TSV input
python3 conv-ics.py events.tsv > events.ics

# A .csv file that actually uses TAB: force the input delimiter
python3 conv-ics.py --delimiter $'\t' events.csv > events.ics
```

ISO-style timestamps in the input (`YYYY-MM-DD HH:MM:SS`, `YYYY-MM-DD HH:MM:SSZ`, `YYYY-MM-DD`) are converted back to iCalendar form (`YYYYMMDDTHHMMSS[Z]`).

### Google Calendar output (default)

The default output layout is a fixed Google Calendar-compatible CSV that can be re-imported into Google Calendar. The column layout and order are fixed regardless of which fields are present in the source file:

| Column        | Source          | Notes                                                |
|---------------|-----------------|------------------------------------------------------|
| `Calendar`    | input basename  | the file's stem (e.g. `work` for `work.ics`)         |
| `Subject`     | `SUMMARY`       |                                                      |
| `Start Date`  | `DTSTART`       | `YYYY-MM-DD` (all-day events have no time)           |
| `Start Time`  | `DTSTART`       | `HH:MM` (24-hour form, no AM/PM)                     |
| `End Time`    | `DTEND`         | `HH:MM` (24-hour form, no AM/PM)                     |
| `Description` | `DESCRIPTION`   |                                                      |
| `Attendee`    | `ATTENDEE`      | Always present in the default output                  |
| `Location`    | `LOCATION`      |                                                      |

Fields that are not relevant for re-import are dropped: `UID`, `DTSTAMP`, `CREATED`, `LAST-MODIFIED`, `SEQUENCE`, `STATUS`, `TRANSP`, `ORGANIZER`, `X-GOOGLE-CONFERENCE`, `RECURRENCE-ID`, `ATTACH`, `RRULE`, `EXDATE`. The `ATTENDEE` column is part of the default layout.

UTC datetimes are converted to local time before being split. The output delimiter can be changed with `--delimiter` (the Google columns are the same). The `--columns` flag is ignored in the default layout (columns are fixed).

```bash
# Single file → Google-format CSV on stdout
python3 conv-ics.py work.ics --output -

# Multiple calendars → one CSV per input file (basename in Calendar column)
python3 conv-ics.py calendars/ --output out/

# Google-format output as TSV
python3 conv-ics.py --delimiter $'\t' calendars/ --output out/

# Opt back into the full iCalendar dump
python3 conv-ics.py --full calendars/ --output out/
```

### Directory mode

A directory can contain a mix of `.ics`, `.csv` and `.tsv` files; each file is routed to the right direction automatically.

```bash
# Convert every file in a directory (default: writes .csv for .ics, .ics for .csv/.tsv)
python3 conv-ics.py calendars/ --output out/

# Same with TSV output for the iCalendar inputs
python3 conv-ics.py --delimiter $'\t' calendars/ --output out/

# Recursive: preserve sub-directory structure
python3 conv-ics.py --recursive calendars/ --output out/
```

### Downloading from a URL

When the positional `input` starts with `http://` or `https://`, the tool downloads the resource into the current working directory and **exits without converting it**. The conversion is a separate second command — this keeps the tool composable and avoids silently making network calls when you only meant to convert a local file.

```bash
# Download a shared calendar to ./basic.ics
python3 conv-ics.py https://calendar.google.com/calendar/ical/.../basic.ics

# Then convert the local copy in a second command
python3 conv-ics.py basic.ics
```

The downloaded filename is derived from the URL:

| URL                                | Saved as                          |
|------------------------------------|-----------------------------------|
| `https://host/foo/basic.ics`       | `basic.ics`                       |
| `https://host/foo/cal?cid=1`       | `cal.ics` (query stripped)        |
| `https://host/foo/cal`             | `cal.ics` (extension appended)    |
| `https://host/`                    | `calendar.ics` (default fallback) |

If a file with the same name already exists in the current directory, the new file is suffixed with `_1`, `_2`, … (`cal_1.ics`, `cal_2.ics`, …) so existing files are never overwritten.

SSL certificate verification is always skipped when downloading (handy for self-signed servers). The network timeout is fixed at 30 seconds.

Network errors (DNS failure, HTTP 4xx/5xx, timeouts) are reported to stderr and the tool exits with a non-zero status; the partial file is not written.

## Default output extension

When `--output` is a directory, the per-file output extension is derived from the input extension and the **output** delimiter:

| Input extension | Direction | Output delimiter         | Output extension          |
|-----------------|-----------|--------------------------|---------------------------|
| `.ics`          | forward   | `,` (CSV default)        | `.csv`                    |
| `.ics`          | forward   | `\t` (via `--delimiter $'\t'`)    | `.tsv`                    |
| `.ics`          | forward   | anything else (via `--delimiter`) | `.txt`                    |
| `.csv`          | reverse   | (auto, `,`)              | `.ics`                    |
| `.tsv`          | reverse   | (auto, TAB)              | `.ics`                    |

## Special columns (`--full` mode)

In `--full` mode the parser keeps every field it encounters and applies the following rules:

| Column                                               | Behavior                                                                                       |
|------------------------------------------------------|------------------------------------------------------------------------------------------------|
| `DURATION`                                           | Computed from `DTSTART` and `DTEND` if not already present in the source event. Format: `Nh`, `Nm`, or `NhMm` (e.g. `1h`, `30m`, `1h30m`). |
| `DTSTART`, `DTEND`, `DTSTAMP`, `CREATED`, `LAST-MOD` | Converted to ISO 8601 by default. `Z`-suffixed values are converted from UTC to local time.   |

The default Google-format output ignores these rules and formats dates/times itself.

## Auto-column mode (`--full`)

When `--full` is set and `--columns` is omitted, the parser returns every field it encounters in the file, sorted by how often it appears (most common first). Ties are broken alphabetically. Specify the wanted columns and their order for cleaner, predictable output. In the default Google-format output, the column layout is fixed and `--columns` is ignored.

## Behavior notes

- The input file's extension determines the direction and the input delimiter.
- `--delimiter` sets both the output and input delimiter, overriding extension-based auto-detection.
- The default forward output is the Google Calendar-compatible CSV layout. Use `--full` to opt back into the original "every field found" dump with ISO date conversion and auto `DURATION`.
- `--columns` only applies in `--full` mode. The Google layout has a fixed column order.
- An `http://` or `https://` input is detected automatically and triggers a download into the current working directory; the tool then exits without converting the file. Run a second `conv-ics.py <downloaded-file>` to convert it. SSL certificate verification is always skipped; the network timeout is fixed at 30 seconds.
- Continuation lines (RFC 5545 line folding) are joined before parsing.
- iCalendar parameters (e.g. `;TZID=America/New_York`) are stripped from the key.
- Backslash-escaped special characters (`\,`, `\;`, `\\`, `\!`...) are unescaped.
- DOS carriage returns are stripped.
- If the `--full` input contains a `DURATION` column with no value, the parser computes it from `DTSTART` and `DTEND`.
- The reverse direction skips empty cells and never emits a `DURATION:` line.
- Output rows are quoted with double quotes only when the value contains the delimiter (RFC 4180-style).

## Compatibility with the original `conv-ics` tool

| Original option         | Python port                                                                  |
|-------------------------|------------------------------------------------------------------------------|
| `--columns <columns>`   | `--columns` (same behavior, same case-insensitive lookup). Requires `--full` in this Python port. |
| `--delimiter <delimiter>` | `--delimiter` (now optional — default is CSV)                         |
| `-x <component>`        | Hard-coded to `VEVENT`                                                       |
| `-n`                    | Removed; ISO date conversion always happens in `--full` mode                 |
| Reverse flag            | Removed; direction is auto-detected from the file extension                  |
| Stdin/stdout pipe       | Not supported; pass a file path and use `--output`                         |
| (new)                   | Extension-based format detection (`.ics`, `.csv`, `.tsv`)                    |
| (new)                   | Default forward output is Google Calendar-compatible CSV; `--full` reverts to the raw dump |
| (new)                   | `http://` / `https://` input is auto-detected and triggers a download (no conversion); SSL verification always skipped; timeout fixed at 30s |

## Testing

```bash
python3 -m unittest discover -s tests -p "test_conv-ics.py"
```

The unit tests cover:
- `DateUtils`: detection, ISO conversion, UTC-to-local, ISO-to-ICS, duration math
- `IcsPreprocessor`: continuation folding, parameter stripping, escape unescaping, CR stripping
- `IcsParser`: record collection, column auto-detection, row building, output formatting
- `IcsBuilder`: CSV/TSV splitting (with quoted values), ICS emission, date round-tripping
- `GoogleCalendarFormatter`: column layout, dropped columns, date/time splitting, quoting
- `IcsHandler`: file/directory processing, dry-run, recursive structure preservation, extension-based format detection, default Google-format output, `--full` opt-in
- `IcsConverterApp`: argparse wiring, delimiter resolution, end-to-end CLI behaviour (default + `--full`)
- `IcsDownloader`: URL detection, filename derivation, collision-safe naming, mocked network success/failure, end-to-end URL entry points (no real network)
