# calendar_generator.py

TangoMan Calendar Generator.

A pure-Python port of `calendar_generator.sh` (a `bash` + `date` + `seq` + `awk` pipeline) following the TangoMan Heel microframework conventions.

## Overview

`calendar_generator` produces a Google Calendar-compatible CSV with one AM entry and one PM entry for every working day (Monday-Friday) in a given date range. The output is ready to be imported straight into Google Calendar through the "Import & export" menu.

The Python port preserves the original feature set while removing every shell dependency: no `bash`, `awk`, `seq`, or external `date` invocations are required at runtime.

## Requirements

- Python 3.10+
- Standard library only (no third-party dependencies)

## Installation


This installs the script to `~/.local/share/TangoMan75/calendar_generator` and creates a symlink in `~/.local/bin/`. Shell completion for bash and zsh is registered automatically. The completion script is generated by the script itself: running `calendar_generator --completion` prints a bash completion script tailored to its own options.

## Usage

```bash
python3 calendar_generator.py [output_file] [options]
```

The output is selected with `--output`. When it is omitted the script writes to `./<calendar_name>.csv` in the current working directory, where `<calendar_name>` is the calendar name converted to lower_snake_case (e.g. `TangoMan` → `tangoman.csv`, `My Calendar` → `my_calendar.csv`). When the calendar name is empty or contains only non-alphanumeric characters, the fallback `calendar.csv` is used.

## Options

| Flag                | Description                                                                                      |
|---------------------|--------------------------------------------------------------------------------------------------|
| `--output`          | Output file path (default: `<calendar_name>.csv` in lower_snake_case, in the current working directory) |
| `--name`            | Calendar name written in the `Subject` column (default: `TangoMan`)                             |
| `--address`         | Address / location written in the `Location` column                                             |
| `--start`           | Start date in `YYYY-MM-DD` format (default: today)                                               |
| `--end`             | End date in `YYYY-MM-DD` format (default: first day of next month)                               |
| `--am-from`         | AM start time in `HH:MM` 24-hour format (default: `09:00`)                                      |
| `--am-to`           | AM end time in `HH:MM` 24-hour format (default: `13:00`)                                        |
| `--pm-from`         | PM start time in `HH:MM` 24-hour format (default: `14:00`)                                      |
| `--pm-to`           | PM end time in `HH:MM` 24-hour format (default: `18:00`)                                        |
| `--gui`             | Launch the graphical user interface (requires `tkinter` and `tkcalendar`)                       |
| `--dry-run`         | Simulate the run without writing any file                                                        |
| `-v`, `--verbose`   | Increase verbosity (stackable: `-v`, `-vv`, `-vvv`)                                              |
| `--quiet`           | Suppress non-error output; runtime errors are still reported                              |

## Output format

The generated CSV follows the Google Calendar import layout:

```csv
Subject,Start Date,Start Time,End Date,End Time,Description,Location
TangoMan,2024-01-01,09:00,2024-01-01,13:00,,Office
TangoMan,2024-01-01,14:00,2024-01-01,18:00,,Office
TangoMan,2024-01-02,09:00,2024-01-02,13:00,,Office
TangoMan,2024-01-02,14:00,2024-01-02,18:00,,Office
```

- One row per AM slot and one row per PM slot
- One entry per working day (Monday through Friday)
- Saturdays and Sundays are skipped automatically
- An invalid `YYYY-MM-DD` string falls back to the default (today for `--start`, first day of next month for `--end`)
- An invalid `HH:MM` string falls back to the corresponding default time

## Examples

### Generate a calendar for the current month

```bash
python3 calendar_generator.py
```

This writes `./tangoman.csv` (the default `TangoMan` subject name in lower_snake_case) for every working day between today and the first day of next month.

### Custom name, address and time ranges

```bash
python3 calendar_generator.py \
    --name "StandUp" \
    --address "1 Rue de la Paix, Paris" \
    --am-from 09:30 --am-to 12:30 \
    --pm-from 14:00 --pm-to 17:30 \
    --start 2024-06-01 --end 2024-06-30
```

### Dry-run to preview without writing

```bash
python3 calendar_generator.py --dry-run --start 2024-01-01 --end 2024-01-31
```

The script reports the number of rows it would have written but does not create a file.

## Graphical user interface

A Tkinter front-end is also available. It mirrors the CLI defaults in a form with a `tkcalendar` date picker for the start and end dates, and entry fields for the calendar name, address, and AM/PM time ranges.

```bash
python3 calendar_generator.py --gui
```

The window opens pre-filled with the same defaults as the CLI (`TangoMan` for the name, today for the start, first day of next month for the end, `09:00-13:00` for AM, `14:00-18:00` for PM). The save dialog is pre-filled with the calendar name converted to lower_snake_case (e.g. `TangoMan` → `tangoman.csv`). Fill in the form, click **Generate**, pick a destination in the save dialog, and the CSV is written using exactly the same `CalendarGenerator` logic as the CLI.

### GUI dependencies

The GUI uses the standard `tkinter` module plus the third-party [`tkcalendar`](https://pypi.org/project/tkcalendar/) library. `tkinter` ships with most Python distributions; `tkcalendar` is installed with:

```bash
pip install tkcalendar
```

If either dependency is missing when `--gui` is invoked, a clear error message is printed instead of a crash. The CLI mode stays fully usable on headless systems where `tkinter` or `tkcalendar` are not available, since the imports are deferred until `--gui` is actually requested.

## Date and time validation

- `--start` / `--end` accept ISO `YYYY-MM-DD` only. Anything else (empty, `not-a-date`, `15/06/2024`, etc.) silently falls back to the default value.
- `--am-from` / `--am-to` / `--pm-from` / `--pm-to` accept `HH:MM` in 24-hour format. Out-of-range values (`25:00`, `09:99`, ...) and malformed strings silently fall back to the corresponding default time.
- If the parsed `--start` is greater than or equal to `--end`, the script exits with a non-zero status and prints a clear error message.

## Default output filename

When neither `--output` nor a positional `output_file` is provided, the script writes to `./<calendar_name>.csv` in the current working directory, where `<calendar_name>` is the calendar name converted to lower_snake_case:

| Calendar name    | Default filename   |
|------------------|--------------------|
| `TangoMan`       | `tangoman.csv`     |
| `StandUp`        | `standup.csv`      |
| `My Calendar`    | `my_calendar.csv`  |
| `My-Calendar!`   | `my_calendar.csv`  |
| `Calendar 2024`  | `calendar_2024.csv`|

The conversion replaces any run of non-alphanumeric characters with a single underscore, strips leading and trailing underscores, and lowercases the result. If the resulting string is empty (the calendar name was empty or contained only non-alphanumeric characters), the fallback `calendar.csv` is used.

## Exit codes

- `0` - Success
- `1` - Validation error (start >= end) or runtime I/O error

## Differences from the original bash script

| Aspect                  | `bash` original                          | Python port                                                                                |
|-------------------------|------------------------------------------|--------------------------------------------------------------------------------------------|
| User input              | Interactive prompts                      | Non-interactive CLI arguments with defaults, plus an optional Tkinter GUI (`--gui`)        |
| Date parsing            | Multiple `date` invocations              | Single `datetime.strptime` call (with regex pre-check)                                     |
| Time iteration          | `seq $START 86400 $END` shell loop       | Pure-Python `timedelta(days=1)` loop                                                       |
| CSV writer              | `echo` and `>>` append                   | `csv.writer` for correct quoting                                                           |
| Weekend detection       | `LANG=en_US date +%A` string comparison  | `date.weekday()` integer comparison                                                        |
